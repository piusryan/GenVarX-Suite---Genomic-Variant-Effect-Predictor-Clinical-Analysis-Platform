================================================================================
                         EXECUTION FLOW
================================================================================

1. USER INPUTS DISEASE NAME
   └─> "Hereditary Breast Cancer"

2. VALIDATE INPUT
   └─> Check length >= 2 chars

3. LAUNCH PARALLEL SEARCHES
   ├─> Task 1: ClinVar search
   ├─> Task 2: Gene search
   ├─> Task 3: Phenotype search
   ├─> Task 4: Drug search (indication-based)
   ├─> Task 5: Drug search (gene-based)
   └─> Task 6: Metadata lookup

4. WAIT FOR ALL TASKS (asyncio.gather)
   └─> All complete in parallel

5. CONSOLIDATE RESULTS
   ├─> Deduplicate entries
   ├─> Calculate statistics
   └─> Limit results per category

6. RETURN RESPONSE
   └─> Complete disease profile

7. FRONTEND DISPLAYS
   └─> Organized in tabs


================================================================================
                      PERFORMANCE CHARACTERISTICS
================================================================================

Typical Response Time: < 2 seconds (local searches)
Result Limits: 
  - Variants: 25
  - Genes: 15  
  - Phenotypes: 20
  - Drugs: 20

Data Volume:
  - ClinVar: ~1M variants
  - HPO: ~20k genes, ~200k phenotypes
  - ChEMBL: ~2M compounds
  - Disease Registry: ~50k diseases


================================================================================
                      COMPARISON: OLD vs NEW
================================================================================

OLD APPROACH (GWAS-based):
  User Input: Variant (e.g., "rs1234567")
         ↓
  Search GWAS Catalog API
         ↓
  Returns: Population associations only
  Problem: No results for rare/pathogenic variants


NEW APPROACH (Disease-based):
  User Input: Disease name (e.g., "Breast Cancer")
         ↓
  Search LOCAL datasets (ClinVar, HPO, ChEMBL)
         ↓
  Returns: Comprehensive disease profile
  Benefit: Works for ALL diseases with local data
